# Polaris AI Platform

## Overview
Polaris AI is a brand visibility and competitive intelligence platform that analyzes how AI models respond to prompts about companies and their competitors. It extracts citations, mentions, and rankings to calculate visibility scores, and delivers consulting-ready PDF reports and data exports. Multi-tenant, configurable AI model selection, comprehensive analytics.

## User Preferences
Preferred communication style: Simple, everyday language.

## System Architecture

### Frontend
React + TypeScript + Vite + Wouter, shadcn/ui (Radix) + TailwindCSS ("New York" design system). TanStack Query for server data.

- **URL-driven project selection** (Tasks #52/#53). Every project-scoped page resolves the active project as `urlClientId || storedClientId` — URL `?clientId=` wins over `localStorage`. Source of truth: `client/src/hooks/use-selected-client-id.ts`. `ProtectedRoute` syncs URL→store on every navigation. The sidebar appends `?clientId=` to every project-scoped `Link` so middle-click and bookmarks carry the selection through. Pages render a "No Client Selected" empty state when neither is set.
- **Navigation** (Task #86). Sections: Overview → Analysis → Opportunities → Reports → Admin. "Client Catalog" is intentionally absent from the sidebar (the catalog is the home page at `/app/clients`). Project Settings is bottom-pinned. The top-nav project label is a dropdown that opens a search-as-you-type switcher.
- **"Client Configuration" → "Project Settings"** rename is user-visible only — the route (`/app/client-config`), file (`client-configuration.tsx`), and DB schema (`clients.*`) are deliberately unchanged.
- **Body pointer-events guard** (Task #46). Single `useBodyPointerEventsGuard()` hook in `client/src/App.tsx` uses `MutationObserver` to clear stuck `pointer-events: none` after Radix dropdown/dialog cleanup races.
- **Self-service profile** (Task #47). `/app/account/profile` lets any user edit display name + password. Form lives in `client/src/components/account/change-password-form.tsx` (shared between profile and the forced-change `/change-password` interstitial). Display-name PATCH refreshes `AUTH_QUERY_KEY`.
- **Root URL** (Task #44). `/` redirects to `/app/clients`. Marketing landing page left in the repo but unreachable.
- **Error UX kit** (Task #114). App-root `ErrorBoundary` + `NetworkBanner` mounted in `App.tsx`. Reusable primitives in `client/src/components/feedback/` (`ErrorState`, `RetryCard`, `NetworkBanner`, `ApiErrorMessage`) plus `useErrorToast` (renders requestId for support) and `useSlowQueryNotice` (15 s threshold). `queryClient.ts` parses the typed error envelope (see Task #113) — 0 retries on 4xx, 2 retries with backoff on 5xx/network.
- **Permission-aware errors & notification conventions** (Task #131). `client/src/lib/api-errors.ts` centralizes `isPermissionError` / `permissionMessage` / `cleanErrorMessage` / `getApiError` (detect 403 via `ApiError.status`/`code` with a legacy string fallback). `useErrorToast` now renders a friendly "You don't have permission…" + action-specific guidance on 403 (overridable via `opts.permissionMessage`), still appending the requestId; the create-project wizard uses this on 403 and keeps its 409 duplicate-name branch. Remaining native `window.confirm()` prompts (revoke current session, halt running job) were swapped for Radix `AlertDialog` (closes BACKLOG #121a). The error/notification convention (permission vs validation vs server vs network) is written down in `client/src/components/feedback/README.md`.
- **Onboarding wizard resume mode** (Task #133). `CreateClientWizard` takes an optional `existingClientId` prop to re-open guided setup for an existing project (pre-filled from client + competitors + models). Resume mode suppresses auto AI-enrichment, PUTs to the same project (never duplicates), reconciles competitors (delete-then-recreate, idempotent + deduped by `clientId + lower(name)`), and blocks Step 1's create path while hydrating (`isHydratingResume`).
- **Forced change-password 401 recovery** (Task #129). `useLogin.onSuccess` invalidates `AUTH_QUERY_KEY` so `/auth/me` re-probes and verifies the session cookie actually stuck (a cookie that never persisted bounces to `/login` instead of rendering a phantom forced-change screen). `change-password-form.tsx` handles a 401 on submit by clearing the auth snapshot, broadcasting revoked, and redirecting to `/login` with a "please sign in again" message — because the global redirect helper intentionally skips `/api/v1/auth/*`.

### Backend
Express.js + TypeScript, RESTful APIs. Key components: `JobQueue` (background processing), `OpenAI Service`, `Website Crawler`, `Citation Extraction`, `Mention Detection`, `Ranking Parsing`, `Visibility Scoring`. Storage abstraction + service layer. Neon WebSocket pool driver (`drizzle-orm/neon-serverless`) with connection pooling.

**Key features:**
- **Intelligent Website Crawling** — Crawlee (CheerioCrawler + PlaywrightCrawler fallback) and `playwright-extra` for anti-detection.
- **Job Queue Reliability** — restart-safe handling, heartbeat-based auto-resume, checkpoint systems, exponential backoff for frontend polling.
- **AI-Powered Analysis** — manual metadata generation, prompt-run execution against selected AI models, dual-source topic generation.
- **Visibility Scoring V2** — normalized weights; configured AEO scoring model (default `gpt-5.4-mini`) for group-aware LLM ranking detection.
- **Historical Data & Reporting** — historical score tracking; dashboard + opportunities filtering by prompt run; executive PDF reports with two-pass summarization and JSON-structured narrative.
- **Unified Reporting** — both client-facing Insights Reports and Technical Diagnostic Appendices generated as parallel PDFs from a single background job.
- **Prompt Categorization** — 7-category taxonomy with AI classifier. **Intent Tier axis (Task #89)** is orthogonal: every AI-generated prompt is also tagged `branded` / `semi_branded` / `unbranded` (`prompt_intent_tier` enum on `prompts.intent_tier`) plus a free-text `diagnostic_focus`. Legacy/manual prompts keep `intent_tier = NULL`.
- **Report Aggregation** — structured aggregation, consulting benchmarks, SWOT-style insights, quality enforcement.

### Data Storage
PostgreSQL via Neon serverless + Drizzle ORM. Multi-tenant schema, UUID PKs, JSONB, enums, timestamp tracking. Drizzle Kit for migrations.

### Authentication & Authorization
`express-session` + `passport` (local strategy) with a **Postgres-backed session store** via `connect-pg-simple` (Task #8) — `createSessionStore()` in `server/auth.ts` reuses the Neon pool, auto-creates the `session` table, and prunes expired rows hourly. `SESSION_SECRET` is required in production; `SESSION_STORE=memory` falls back to `memorystore` for tests. Passwords are Argon2id.

RBAC roles: `viewer`, `member`, `admin`. Layered access: global guard + per-route role checks + `server/privileges.ts` matrix. **Org membership alone does not grant project access** — `client_user_grants` records per-user/per-project visibility (Task #26). Admin module at `/app/admin/{users,projects,queue,audit,models}` (shared visual primitives in `client/src/pages/admin/_shared.tsx`). Public registration off by default — credential-grant invitation flow.

**Self-demotion guard** (Task #130). `PATCH /api/v1/admin/orgs/:orgId/members/:userId` rejects with 403 ("You cannot change your own role — ask another admin") when the target equals the caller, placed before the existing last-admin check (which is left intact). The admin Members UI disables the role selector for the caller's own row (`isSelf` via `useAuth().user.id`) and bulk role changes filter out the caller's own row. Prevents the production footgun where an admin demoted themselves to `viewer` and lost access to the admin screen.

**Tenant resolution from URL path** (Task #132). `resolveTenant()` in `server/auth.ts` extracts the client id from the request URL with an `/api/v1`-tolerant regex and treats the path-derived id as authoritative (after `req.params.clientId`, before body/query/`x-client-id` header). This binds auth to the resource named in the URL instead of a stale selected-project header (security-positive) and fixed the create-project wizard freezing for first-project / incognito users who had no `x-client-id` header to fall back on.

**Auth & session audit** (Task #125). `docs/audits/AUTH_SESSION_AUDIT_2026-06-01.md` is a read-only, evidence-anchored security review of login/session/CSRF/RBAC/grants. Posture: strong for internal use, not yet bank-grade (top gaps: no MFA, no email delivery for resets/invites, HSTS doc/code discrepancy). Audit-class docs live in `docs/audits/` (see `docs/audits/README.md`).

**Session hardening** (Tasks #37 / #42). Login + register call `req.session.regenerate()` (defeats session-fixation). `polaris.csrf` double-submit cookie on every state-changing `/api/v1` call. Per-IP `express-rate-limit` on login / register / forgot-password. `user_sessions` ledger + `server/services/sessions.ts` powers `/app/account/sessions` (revoke + "Sign out of all other sessions" bumps the user's `sessionEpoch`). Idle (7 d users / 24 h admins) + absolute (30 d) timeouts; `rememberMe` toggles persistent vs browser-session cookie. `BroadcastChannel("polaris-auth")` keeps sibling tabs in sync. `helmet` with dev-vs-prod CSP. Task #42 keeps the ledger and the `session` table in lock-step (`EXISTS` filter + hourly orphan sweep).

### LLM model configuration (Task #38)
Single source of truth: `server/config/llm-functions.ts`. Each of the 14 internal LLM call sites resolves via `LLM_<FUNCTION>_MODEL` env → legacy `REPORT_AI_MODEL` / `LLM_MODEL` → `LLM_FUNCTION_DEFAULTS` (GPT-5.4 family + `claude-sonnet-4-5` for AEO Anthropic). Resolved table logged at boot. `ai_models` seed is idempotent (`upsertMissingModels`, `syncModelCategories`, `disableDeprecatedModels`). Full inventory: `docs/audits/LLM_PROVIDER_AUDIT_REPORT_2026-05-05.md`.

### Reliability & operations
- **Backend error contract & observability** (Task #113). Every non-2xx `/api/v1` response is `{ error: { code, message, requestId, details? } }`. Single serializer in `server/middleware/error-handler.ts` (does NOT re-throw). Throw `ApiError` or let Zod errors bubble. Postgres driver codes translated by `server/utils/db-errors.ts`. Request ids stamped by `server/middleware/request-id.ts` (`req.id`, `X-Request-Id`, `req.log`). `unhandledRejection` / `uncaughtException` log + bump `processHealth` counters without `process.exit()`. `/health` (readiness, 503 on DB ping fail) + `/health/live` (always 200 if event loop responsive). Per-user rate limits on the four heavy write endpoints (refresh-prompts, reports/generate, prompt-runs, xray/analyze/batch). Code catalog + examples: `server/README-errors.md`.
- **Operational recovery, retries & alerting** (Task #115). `prompt_runs.heartbeat_at` stamped every 30 s by `executePromptRun`; reaper at `server/services/prompt-run-reaper.ts` prefers `heartbeat_at` over `createdAt`. Periodic `startStalePromptRunSweep` runs every 10 min (env `STALE_PROMPT_RUN_SWEEP_MS` or `_INTERVAL_MS`). LLM retry budget in `server/llm/retry.ts` (full-jitter backoff 250 ms→4 s, 3 attempts, 10 s budget on 408/429/5xx; `VendorPausedError` short-circuits). Admin Retry / Cancel / Halt at `POST /api/v1/admin/jobs/:id/{retry,cancel,halt}` — cancel is atomic via `storage.cancelQueuedJob`; halt (Task #121) uses `jobQueue.cancelJob()`. Alert sink at `server/services/alert-sink.ts` routes to console + Slack (`ALERT_SLACK_WEBHOOK_URL`) + email (`ALERT_EMAIL_SMTP_URL` + `nodemailer`); 5-min in-process dedupe; triggers: `alertJobFailure` (gated on `resumeCount >= MAX_RESUME_ATTEMPTS`), `alertVendorPause`, `alertHealthDbDown`, `alertUnhandledRejection`. Operational dashboard at `/app/admin` (queue tiles, failures-by-kind, `/health` snapshot, per-provider 24h error rates, recent failures). Providers panel shows color-graded 24 h error rate. Runbook in `ISSUE_LOG.md` → "Alerts & Recovery".
- **Provider health & vendor kill switch** (Task #78). `ai_vendor_status` table backs a per-vendor pause flag (with attribution). Cache in `server/config/vendor-pause.ts` (30 s TTL). `executePrompt` short-circuits paused vendors with 503. Consumer `/api/v1/ai-models` filters paused vendors out; admin catalog still returns them with `isVendorPaused`. Internal LLM call sites that bypass `executePrompt` (narrative generator, competitor discovery, prompt classifier, X-Ray analyzer, openai-service, response summarizer, recommendation analyzer, `server/llm/{openai,anthropic}.ts`) gate via `assertVendorNotPaused(vendor)`. Long-lived entry points `await ensureVendorPauseLoaded()` to defeat cold-cache.
- **Site X-Ray batch worker** (Task #58). `processXRayAnalysis` handler in `server/services/job-queue.ts` ensures `page_structures` exist, runs `analyzeBatchPages` in chunks of 5 with retry/backoff. `recoverStaleJobs()` fails any `xray_analysis` row older than 15 min. Does NOT fan out to `recommendations` (still in `generateMetadata`).
- **Stale prompt-run reaper** (Task #59 — superseded by Task #115's heartbeat-aware periodic sweep). Boot-time one-shot still runs to clear pre-existing zombies from prior crashes.
- **Refresh Prompts speed + crash-safety** (Task #98). `POST /api/v1/clients/:id/refresh-prompts` classifies in parallel (5-way) and wraps delete + bulk insert in a single `db.transaction(...)`; mid-batch failure rolls back so existing prompts are preserved. Classification stays best-effort (single failure falls back to `categoryId = null`).
- **Active operations visibility** (Task #56). `GET /api/v1/clients/:clientId/activity` + `GET /api/v1/clients/activity-summary` (`server/services/activity-service.ts` reads jobs / promptRuns / reportJobs). Every async enqueue records `startedByUserId`. `useClientActivity(clientId)` polls every 5 s (paused while hidden); `<ActiveOperationsBanner>` + `<ActivityChip>` surface status. Soft-disable: Refresh Prompts (during `refresh_prompts`), Duplicate (during `project_copy`), StartRunDialog warns during in-flight `prompt_run` (no hard locks). Job→ActivityKind mapping in `activity-service.ts`.

### Notable per-feature implementation notes
- **Realism-aware Prompt Library generator** (Task #89). `generateRealisticPrompts` in `server/openai-service.ts` accepts a full project-context envelope (incl. `targetCustomerPersona`, `targetMarketCountry`, `primaryTestLocation`, `primaryLanguage`) and asks the model for ~18 prompts split across Branded / Semi-Branded / Unbranded tiers with a short `diagnosticFocus`. Geography never concatenated ("operating in <country>" forbidden); each field on its own labeled line. `near me` resolves to `primaryTestLocation` when present. Sector-specific exemplar hints from `server/services/prompt-sector-patterns.ts`. The Prompt Library page shows tier badges + filter + tooltip; the four context fields are edited from "AI Visibility Context" card on project config.
- **Executive Report PDF filenames** (Task #110). Both PDF download endpoints + on-disk paths use `server/utils/report-filename.ts::buildReportFileName()` → `Polaris_<Insights|Technical_Appendix>_<Client>[_-_<Project>]_<YYYY-MM-DD>_<id8>.pdf`. Smart dedupe trims/drops project segment when it starts with or equals the client name. Date = `report_snapshots.generated_at` UTC. `Content-Disposition` uses both `filename=` and RFC-5987 `filename*=UTF-8''…`. On-disk paths keep the `_<timestamp>` suffix; the download route serves whatever `report_files.file_url` records, so old-shape files keep working.
- **Prompt run naming + rerun CTA** (Task #107). Auto-fallback name is `buildAutoRunName(runId)` → `Run <id8> · <MMM d>`. Prompts Tracker has a Rerun icon on every row (disabled while source is non-terminal). Confirm dialog fetches `/api/v1/prompt-runs/:id/selections`, shows source name/status/counts + concurrent-run warning. Confirm POSTs to `POST /api/v1/prompt-runs` with optional `iterationOf`; server scans existing runs and stores `<base> (iteration K+1)` — server-side N prevents most collisions. No new routes, no schema; a real `parent_run_id` column is filed as follow-up #107a.

## Gotchas
- **Production URL**: `https://polaris-r3.ignitelabs.online` (vm-target deploy, runs `npm run start` → `NODE_ENV=production node dist/index.js`).
- **Dev and prod use separate Neon databases.** The dev workflow's `DATABASE_URL` and the prod VM's `DATABASE_URL` point at different Neon DBs. Project renames, prompt runs, topics, and uploads created on one do NOT appear on the other. (Caught us once: "Masafi looks empty in prod" — data lived only in dev DB.) Production data must be created against the production deployment.
- **`.config/pulse/` is in `.gitignore`** because Chromium-under-Playwright creates PulseAudio runtime symlinks pointing at `/tmp/pulse-XXXX` dirs cleaned up on workflow exit. Without the ignore, every Repl layer push warned `Detected broken symlink`.
- **`.replit` is the source of truth for deploy config** (vm target, build/run commands, port mapping). Do not move start commands into `package.json` scripts assumptions.
- **Dev server does not auto-reload on backend edits.** `npm run dev` runs plain `tsx server/index.ts` (no watch), so edits to anything under `server/` require a workflow restart. If the frontend HMRs ahead of a server restart, new API routes may briefly return the Vite SPA HTML and surface as `Unexpected token '<'` JSON parse errors in the UI (filed as follow-up #121c/#121d).
